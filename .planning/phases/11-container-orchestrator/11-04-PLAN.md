<objective>
Build the HTTP API server that exposes container orchestration to the Rachel Cloud control plane, and create the systemd service for production deployment.

Purpose: The SvelteKit control plane (web dashboard) needs to create, destroy, restart, and monitor containers. It does this by calling the orchestrator's HTTP API on localhost:9998. This is the same pattern as the LLM proxy (localhost:9999) — internal services communicating over HTTP on the loopback interface.

Output: src/orchestrator/server.ts (HTTP API) and ops/rachel-cloud-orchestrator.service (systemd unit).
</objective>

  <action>
    Create `/home/rachel/rachel-cloud/src/orchestrator/server.ts`:

    ```typescript
    /**
     * Rachel Cloud Container Orchestrator API
     *
     * Internal HTTP API for managing Docker containers.
     * Called by the SvelteKit control plane.
     *
     * Usage: ORCHESTRATOR_API_KEY=xxx bun run src/orchestrator/server.ts
     * Port: 9998 (configurable via ORCHESTRATOR_PORT)
     * Binds: 127.0.0.1 only (not accessible from outside)
     */
    ```

    **Authentication:**
    - All endpoints (except GET /health) require `Authorization: Bearer {ORCHESTRATOR_API_KEY}` header
    - `ORCHESTRATOR_API_KEY` loaded from env (required, exit if missing)
    - Return 401 if missing/invalid

    **Routes:**

    1. `POST /containers` — Provision a new user container
       - Body: `{ userId: string, telegramBotToken: string, ownerTelegramUserId: string, groqApiKey?: string }`
       - Calls `provisionContainer(userId, env)`
       - Returns: `{ status: "ok", container: ContainerStatus }` (201)
       - On error: `{ status: "error", message: "..." }` (500)

    2. `DELETE /containers/:userId` — Deprovision a container
       - Query param: `?removeData=true` for destructive cleanup
       - Calls `deprovisionContainer(userId, removeData)`
       - Returns: `{ status: "ok" }` (200)
       - On error: `{ status: "error", message: "..." }` (500)

    3. `GET /containers` — List all containers
       - Calls `listAllContainers()`
       - Returns: `{ status: "ok", containers: ContainerStatus[] }` (200)

    4. `GET /containers/:userId` — Get single container status
       - Calls `getContainerStatus(userId)`
       - Returns: `{ status: "ok", container: ContainerStatus }` (200)
       - If not found: `{ status: "error", message: "Container not found" }` (404)

    5. `POST /containers/:userId/restart` — Restart a container
       - Calls `restartContainer(userId)`
       - Returns: `{ status: "ok", container: ContainerStatus }` (200)

    6. `POST /containers/:userId/update` — Update single container
       - Body: `{ image?: string }` (optional, defaults to latest)
       - Calls `updateContainer(userId, image)`
       - Returns: `{ status: "ok", result: UpdateResult }` (200)

    7. `POST /update-all` — Rolling update all containers
       - Body: `{ image?: string }` (optional)
       - Calls `updateAllContainers(image)`
       - Returns: `{ status: "ok", result: UpdateAllResult }` (200)
       - Note: This can take minutes for many containers — return result when done

    8. `POST /sweep` — Trigger manual health sweep
       - Calls `runHealthSweep()`
       - Returns: `{ status: "ok", result: HealthSweepResult }` (200)

    9. `GET /health` — Orchestrator health (no auth required)
       - Check Docker connectivity (docker.ping())
       - Return uptime, Docker status, container count
       - Returns: `{ status: "ok", uptime: number, docker: boolean, containers: number }` (200)

    **Startup:**
    - Validate ORCHESTRATOR_API_KEY is set
    - Start health monitor (background)
    - Start Bun.serve() on 127.0.0.1:9998

    **Shutdown:**
    - Stop health monitor
    - Stop server
    - SIGTERM/SIGINT handlers

    **Request logging:**
    - Log method, path, userId (if present), response status, duration
    - Do NOT log request bodies (may contain tokens)
