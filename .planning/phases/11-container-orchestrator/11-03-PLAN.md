  <action>
    Add two new exported functions to `container-manager.ts`:

    **1. `updateContainer(userId: string, newImage?: string): Promise<UpdateResult>`**

    ```typescript
    export interface UpdateResult {
      userId: string;
      success: boolean;
      previousImage: string;
      newImage: string;
      durationMs: number;
      error?: string;
      rolledBack?: boolean;
    }
    ```

    Algorithm:
    ```
    1. Inspect existing container → get current image, env vars
    2. If current image === newImage → return (already updated)
    3. Record the old image tag for rollback
    4. Stop container (10s timeout)
    5. Remove container
    6. Create new container with newImage (same env, same volume)
    7. Start new container
    8. Wait for healthy (poll every 2s for up to 60s)
    9. If healthy → return success
    10. If not healthy after 60s:
        a. Stop new container
        b. Remove new container
        c. Recreate with OLD image
        d. Start old container
        e. Return { success: false, rolledBack: true }
    ```

    The `newImage` parameter defaults to `config.imageName` (usually "rachel8:latest"). This allows updating to a specific tagged version.

    Must reconstruct the container's env vars from the inspect response, since we need to preserve TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_USER_ID, etc.

    **Helper: `waitForHealthy(containerName: string, timeoutMs: number): Promise<boolean>`**
    - Poll `docker.inspectContainer()` every 2 seconds
    - Return true if health status becomes "healthy"
    - Return false if timeout expires
    - Handle "starting" as "still waiting"

    **2. `updateAllContainers(newImage?: string, onProgress?: UpdateProgressCallback): Promise<UpdateAllResult>`**

    ```typescript
    export type UpdateProgressCallback = (progress: {
      total: number;
      completed: number;
      current: string;        // userId being updated
      results: UpdateResult[];
    }) => void;

    export interface UpdateAllResult {
      total: number;
      succeeded: number;
      failed: number;
      rolledBack: number;
      skipped: number;
      results: UpdateResult[];
      durationMs: number;
    }
    ```

    Algorithm:
    ```
    1. List all rachel-user-* containers
    2. For each container (sequentially):
       a. Call onProgress with current state
       b. Call updateContainer(userId, newImage)
       c. If failed, continue to next (don't stop fleet update)
       d. If rolled back, log warning but continue
    3. Return aggregate results
    ```

    Sequential by default (one at a time) to minimize disruption. If a container fails, it's rolled back individually and the update continues.
