# Plan 14-05: Telegram Bot Commands — /start, /status, /restart, /logs, /billing, /help

## Goal
Add management commands to the shared Rachel bot so users can do quick tasks without opening the web dashboard.

## Commands

### /start
Triggered when user first messages the bot. Different responses based on subscription status:
- **No account**: Welcome message + link to subscribe
- **Active subscriber, no container**: "Setting up your instance..." + auto-provision
- **Active subscriber, running**: "Welcome back! Just message me anything."

### /status
Returns container status:
```
🟢 Your Rachel instance is running
Uptime: 3 days, 2 hours
Image: rachel8:latest
```
Or: `🔴 Your Rachel instance is stopped`

### /restart
Restarts the user's container:
```
♻️ Restarting your Rachel instance...
✅ Restart complete! Rachel is back online.
```

### /logs
Returns last 20 log lines from the container (truncated for Telegram's message limit).

### /billing
Shows subscription status + link to web dashboard for payment management:
```
📋 Subscription: Active
Next billing: March 16, 2026
💳 Manage billing: https://get-rachel.com/dashboard/billing
```

### /help
Lists available commands.

## Implementation

Commands are handled in the message router BEFORE forwarding to the container:

```typescript
// In src/lib/telegram/router.ts
const text = update.message?.text;

if (text?.startsWith('/')) {
  // Handle commands at router level
  switch (text.split(' ')[0]) {
    case '/start': return handleStart(telegramId);
    case '/status': return handleStatus(telegramId);
    case '/restart': return handleRestart(telegramId);
    case '/logs': return handleLogs(telegramId);
    case '/billing': return handleBilling(telegramId);
    case '/help': return handleHelp(telegramId);
    default: break; // Unknown command — forward to container
  }
}

// Not a command — forward to container
await forwardToContainer(containerName, update);
```
