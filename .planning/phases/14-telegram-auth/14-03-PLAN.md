# Plan 14-03: Shared Bot Message Router

## Goal
Build a message router that receives all Telegram messages via a single shared bot, looks up the user's container, forwards the message, and returns the response.

## Architecture

```
Telegram → Webhook → Router (SvelteKit) → Orchestrator → Container
                                                              ↓
Telegram ← Response ← Router ← Orchestrator ← Container response
```

## How Message Forwarding Works

### Option A: HTTP API in each container (Recommended)
Each Rachel8 container exposes an internal HTTP endpoint (e.g., `POST /message`) on the Docker network. The router:
1. Receives Telegram update via webhook
2. Looks up user's container by `telegram_id` → gets `container_name`
3. POSTs the message to `http://{container_name}:3000/message`
4. Container processes via Claude Agent SDK
5. Container responds with the reply text
6. Router sends reply back via Telegram Bot API

### Option B: Pass-through bot token
Each container already runs its own grammY bot instance. Instead of routing messages, we could:
1. Register the shared bot's webhook to the router
2. Router forwards the raw Telegram update to the container
3. Container processes it as if it received it directly
4. Container sends the reply via Bot API using the shared bot token

**Recommendation:** Option B is simpler — containers already know how to handle Telegram updates. We just need to proxy the raw update JSON to the right container.

## New Files

### `src/routes/api/telegram/webhook/+server.ts` — Webhook Receiver
```typescript
// POST /api/telegram/webhook
// Receives ALL updates from the shared Rachel bot
export async function POST({ request }) {
  const update = await request.json();

  // Extract telegram_id from update
  const telegramId = update.message?.from?.id
    || update.callback_query?.from?.id
    || update.edited_message?.from?.id;

  if (!telegramId) return json({ ok: true }); // Ignore unsupported updates

  // Look up user + container
  const user = await getUserByTelegramId(telegramId);

  if (!user || !user.subscription?.containerId) {
    // Unknown user or no container — handle /start, /subscribe etc.
    await handleUnsubscribedUser(telegramId, update);
    return json({ ok: true });
  }

  // Forward raw update to user's container
  await forwardToContainer(user.subscription.containerName, update);

  return json({ ok: true });
}
```

### `src/lib/telegram/router.ts` — Routing Logic
```typescript
export async function forwardToContainer(containerName: string, update: any) {
  // Each container exposes a webhook endpoint on the Docker network
  const url = `http://${containerName}:8443/webhook`;
  await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(update),
  });
}

export async function handleUnsubscribedUser(telegramId: number, update: any) {
  const text = update.message?.text;

  if (text === '/start') {
    await sendTelegramMessage(telegramId,
      "👋 Hi! I'm Rachel, your personal AI assistant.\n\n" +
      "Subscribe for $20/mo to get started:\n" +
      "https://get-rachel.com/subscribe\n\n" +
      "Already subscribed? Log in at https://get-rachel.com/login"
    );
  } else {
    await sendTelegramMessage(telegramId,
      "You don't have an active subscription. Visit https://get-rachel.com to get started!"
    );
  }
}
```

## Webhook Registration
Set the shared bot's webhook to point to our endpoint:
```bash
curl "https://api.telegram.org/bot{TOKEN}/setWebhook?url=https://get-rachel.com/api/telegram/webhook"
```

## Container Side Changes
Each Rachel8 container needs to:
1. Accept forwarded updates on an internal HTTP port (already does this via grammY webhook mode)
2. Use the shared bot token to send replies (passed via env var)
3. NOT register its own webhook (the router handles that)

## Docker Network
Containers must be on the same Docker network as the control plane:
- Control plane can reach containers by name: `http://rachel-{userId}:8443/webhook`
- Containers can reach the LLM proxy: `http://host.docker.internal:9997`
