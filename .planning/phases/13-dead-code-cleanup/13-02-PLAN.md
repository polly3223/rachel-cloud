# Plan 13-02: Schema Cleanup — Remove healthChecks Table & Legacy VPS Columns

## Goal
Remove dead database artifacts: the `healthChecks` table (SSH-based health tracking) and legacy VPS columns from the `subscriptions` table.

## Schema Changes

### Remove `healthChecks` Table
Delete the entire table definition from `src/lib/db/schema.ts`. This table tracked:
- `userId`, `status` (healthy/unhealthy/unknown)
- `consecutiveFailures`, `lastCheckAt`
- `circuitState` (closed/open/half_open), `circuitOpenedAt`
- `lastRestartAt`, `totalChecks`

### Remove Legacy VPS Columns from `subscriptions`
These columns are nullable and unused (Docker uses `containerId`, `containerName`, `currentImage`, etc.):

| Column | Type | Action |
|--------|------|--------|
| `hetznerServerId` | integer | DELETE |
| `hetznerSshKeyId` | integer | DELETE |
| `vpsIpAddress` | text | DELETE |
| `vpsHostname` | text | DELETE |
| `sshPrivateKey` | text | DELETE |
| `currentVersion` | text | DELETE |
| `targetVersion` | text | DELETE |
| `previousVersion` | text | DELETE |
| `lastUpdateAt` | timestamp | DELETE |

### Rename `vpsProvisioned` → keep as-is (pragmatic)
The `vpsProvisioned` column is used in 6+ live files as a "is provisioned?" flag. Renaming it would require a migration AND updating every reference. Since it's just a column name (not user-facing), keep it and add a comment:
```typescript
// Legacy name — means "container provisioned" in Docker model
vpsProvisioned: integer('vps_provisioned', { mode: 'boolean' })
```

### Any file importing `healthChecks` from schema

## Migration Strategy
SQLite doesn't support `ALTER TABLE DROP COLUMN` in older versions, but Bun's SQLite does (SQLite 3.35+). Options:
1. **Drizzle push** — `bun drizzle-kit push` will handle column removal
2. **Manual migration** — if push doesn't work, create a migration that recreates the table

Since there are no production users yet, Drizzle push is fine.

## Order of Operations
1. Edit `schema.ts` — remove healthChecks + VPS columns
2. Remove any `healthChecks` imports/relations from schema
3. Run `bun drizzle-kit push` (or generate + run migration)
4. Verify schema with `bun drizzle-kit studio` or direct SQLite query
