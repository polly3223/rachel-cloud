<objective>
Build the core LLM proxy server: a Bun HTTP server that receives Anthropic-compatible API requests from Docker containers, injects Z.ai authentication, forwards to the Z.ai API, and streams SSE responses back transparently.

Purpose: This is the foundation of Rachel Cloud's shared LLM infrastructure. Without the proxy, containers cannot access the Z.ai GLM API. The proxy centralizes auth (Z.ai key stays on host), enables per-user tracking (later plans), and provides a single point for rate limiting and monitoring. This plan establishes the request/response pipeline; rate limiting and usage persistence are added in plan 10-02.

Output: src/proxy/server.ts (entry point), src/proxy/forward.ts (forwarding + SSE streaming), src/proxy/config.ts (configuration) -- all in the rachel-cloud repo under src/proxy/.
</objective>

  <files>/home/rachel/rachel-cloud/src/proxy/forward.ts</files>
  <action>
    Create `/home/rachel/rachel-cloud/src/proxy/forward.ts` that handles forwarding requests to Z.ai and streaming responses back.

    **Exports:**

    1. `extractUserId(req: Request): string | null` -- Extracts user ID from the Authorization header. The Claude Agent SDK sends ANTHROPIC_AUTH_TOKEN as the Authorization header. Each container has `ANTHROPIC_AUTH_TOKEN=rachel-user-{USER_ID}`. The function parses this:
       ```typescript
       export function extractUserId(req: Request): string | null {
         const auth = req.headers.get("authorization");
         if (!auth) return null;
         // Support both "rachel-user-{id}" and "Bearer rachel-user-{id}"
         const token = auth.replace(/^Bearer\s+/i, "");
         const match = token.match(/^rachel-user-(.+)$/);
         return match ? match[1] : null;
       }
       ```

    2. `forwardToZai(req: Request, userId: string): Promise<Response>` -- The core forwarding function. It:

       a. Reads the request body as JSON
       b. Builds the upstream URL: `${config.upstreamBaseUrl}/v1/messages`
       c. Constructs upstream headers:
          - `content-type: application/json`
          - `authorization: Bearer ${config.zaiApiKey}` (inject Z.ai key)
          - `anthropic-version`: forward from original request (default to `2023-06-01` if missing)
          - `anthropic-beta`: forward from original request (if present)
          - Do NOT forward the container's Authorization, X-Rachel-User-ID, host, or connection headers
       d. Fetches from upstream with these headers and the original body
       e. If the request body has `"stream": true`:
          - Returns a streaming response using a TransformStream
          - The TransformStream passes all SSE data through to the client byte-for-byte
          - In the transform function, accumulate text chunks and scan for `message_start` and `message_delta` events to extract token counts
          - In the flush function, call a callback with the extracted usage data
          - Return type: `{ response: Response, usagePromise: Promise<UsageData> }`
       f. If the request body does NOT have `"stream": true`:
          - Read the upstream response as JSON
          - Extract `usage.input_tokens` and `usage.output_tokens` from the response
          - Return the response to the client
          - Return type: `{ response: Response, usagePromise: Promise<UsageData> }`

    3. `UsageData` interface:
       ```typescript
       export interface UsageData {
         userId: string;
         model: string;
         inputTokens: number;
         outputTokens: number;
         durationMs: number;
         timestamp: number;
         streaming: boolean;
       }
       ```

    **SSE Token Extraction Logic:**

    The TransformStream processes chunks of text. SSE events are separated by `\n\n`. Within the transform function:

    - Maintain a text buffer that accumulates incoming chunks (decoded from Uint8Array)
    - When the buffer contains complete SSE events (delimited by `\n\n`), parse them
    - For `event: message_start` -- extract `data.message.usage.input_tokens`
    - For `event: message_delta` -- extract `data.usage.output_tokens` (this is cumulative, take the last value)
    - Use a simple line-by-line parser: when you see a line starting with `event: `, note the event type; when you see a line starting with `data: `, parse the JSON for that event type
    - Do NOT try to parse every line as JSON -- only parse data lines for message_start and message_delta events
    - If JSON parsing fails for any event, skip it silently (do not corrupt the stream)

    **Important implementation details:**

    - The TransformStream MUST pass through ALL bytes unmodified to the client. The usage extraction is read-only observation.
    - Encode/decode: The upstream sends UTF-8 text. Use TextDecoder/TextEncoder for the parsing side. The enqueue side should pass the original Uint8Array chunk unchanged.
    - Handle the case where an SSE event spans multiple chunks (buffer partial events)
    - Set a timeout on the upstream fetch (120 seconds) to prevent hung connections

    **Error handling:**
    - If upstream fetch throws (network error), return a 502 response with JSON error body: `{"type": "error", "error": {"type": "proxy_error", "message": "Upstream connection failed"}}`
    - If upstream returns 4xx/5xx, pass the response through to the client unchanged (including status code and body)
    - Log all errors with userId and request details

    **Full function signature:**
    ```typescript
    export async function forwardToZai(
      req: Request,
      userId: string,
    ): Promise<{ response: Response; usagePromise: Promise<UsageData> }> {
      // ... implementation
    }
    ```

             outputTokens: usage.outputTokens,
             durationMs: usage.durationMs,
